| Путь | Назначение |
| --- | --- |
| `src/main/java/ru/servermine/forge/ForgeSystemPlugin.java` | Жизненный цикл, события и команды |
| `ForgeMenuService.java` | Горн, входные слоты, кнопки и рецепты |
| `ForgingService.java`, `ForgeSession.java` | Сессии ковки, удары, охлаждение и завершение |
| `ForgeItems.java`, `Model.java`, `ForgeItemsApi.java` | Подписанные предметы и допустимые состояния |
| `DurableStore.java`, `StorageSelfTest.java` | Журнал, возврат предметов и восстановление |
| `Settings.java` | Проверка конфигурации и миграция настроек |
| `EquipmentRules.java`, `EquipmentRecipes.java`, `EquipmentSelfTest.java` | Ограничение крафтов, правила алмазного улучшения и серверные проверки |
| `PackService.java`, `ItemSprites.java` | Раздача ресурспака и выбор температурной модели |

| `tools/vanilla-items` | Ванильные исходники для геометрии и предпросмотра |

Имена Java-файлов без полного пути в таблице находятся в том же пакете `src/main/java/ru/servermine/forge`.

## Сборка ресурспака

Задача Gradle `buildResourcePack` запускает генератор на Java 25 перед `processResources`. Она создаёт `resourcepack/`, PNG-предпросмотры и `src/main/resources/forge.zip`. Этот ZIP встраивается в JAR. Производные файлы исключены из Git; исходники `tools/` отслеживаются.

Модели заготовок ссылаются на текстуры клиента `minecraft:item/*`. Для инструмента сохраняются только металлические участки геометрии. Цветовой вариант зависит от фактической температуры и порога материала; готовый предмет сбрасывает пользовательскую модель.

## Предметы и сохранение

PDC namespace — `forgesystem`; схема предметов — 1. UUID, материал, состояние, качество, этапы, владелец, блокировка, температура и ревизия входят в подписываемые данные. Имя и lore не являются доказательством подлинности.

Игровые операции выполняются на основном потоке. Входы горна хранятся отдельно от инвентаря; при закрытии возвращаются игроку или в очередь `/forge claim`. Изменения инвентаря проходят через `DurableStore`. Изменяя переходы состояния, не обходите проверки `ForgeItems.change` и журнал.

## Проверяемые сценарии

В версии 3.1.0 имеется 30 JUnit-тестов: температура, топливо, ковка, модели, миграция настроек, границы ограничения рецептов, стоимость улучшения и перенос износа. Команда `forge selftest` дополнительно проверяет все девять улучшений: сохранение данных и зачарований, сериализацию, расход алмазов, отказ при недостатке, повторное улучшение и защиту подписи.

Алмаз не добавляется в `Metal`: исходная железная основа и её Workpiece остаются прежними. Дополнительный PDC `equipment_tier=DIAMOND` разрешён только для FINISHED/IRON и включается в HMAC как суффикс канонических данных. Для предметов без этого поля схема и подпись не меняются. `upgradeInventory` вызывается внутри `DurableStore.transact`.

Репозиторий не содержит игровой сервер, миры или ключ подписи. Для серверных проверок создавайте отдельную установку той же версии с отдельными портами; не используйте рабочие данные игроков как тестовые фикстуры.
