# Разработка

## Начало работы

Нужны Git, JDK 25 и доступ к Maven Central / репозиторию Paper. Gradle устанавливается через Wrapper. Сборка не требует установленного Minecraft-сервера.

```sh
git switch main
git pull --ff-only
git switch -c feature/short-description
./gradlew build
```

В PowerShell используйте `.\gradlew.bat` вместо `./gradlew`. Генератор ресурспака запускается автоматически; отдельно его можно выполнить командой `./gradlew buildResourcePack`.

## Проверка изменений

- Всегда выполняйте `./gradlew build` перед PR.
- Для механик предметов проверяйте сохранение UUID, HMAC, этапов и температурного якоря.
- Для изменений хранения тестируйте миграцию и восстановление на копии данных.
- Для графики проверьте предпросмотр и настоящий клиент; укажите, если игровая проверка ещё не выполнена.
- На отдельном Paper/Purpur-сервере запускайте `forge selftest` и `forge status` из консоли.

Selftest проверяет кодек предметов, смену температурных моделей, миграцию молота, обработку ПКМ и журнал восстановления. Она не заменяет ручную проверку управления клиентом и взаимодействий с другими плагинами.

## Pull request

Работайте в отдельных ветках, основной код хранится в `main`. В PR опишите проблему, результат, проверки и порядок обновления. Для новых функций сначала уточните критерии в Issue; отправная точка — [ROADMAP.md](ROADMAP.md).

Не коммитьте серверные миры, каталоги игроков, `state.yml`, ключ подписи, пароли и локальные настройки доступа. `.gitignore` исключает стандартные пути. В Git сохраняются исходники и исходная графика; JAR, ZIP и сгенерированные модели собираются заново.

## Подготовка версии

1. Обновите версию в `build.gradle.kts`, `src/main/resources/plugin.yml`, строках статуса/запуска `ForgeSystemPlugin.java` и описании пакета `tools/BuildPack.java`.
2. Обновите README, историю изменений и проверенные пункты roadmap.
3. Выполните чистую сборку, серверную selftest и относящиеся к изменению игровые проверки.
4. Сохраните резервную копию плагина и его данных перед установкой; сохраните `item-signing.key`.
5. Используйте артефакт конкретного коммита из Actions. CI собирает файлы, но не устанавливает их на игровой сервер.

## Графика

Сохраняйте ванильный масштаб 16×16 для предметов. Заготовки инструментов показывают металл без деревянной рукояти; броня сохраняет силуэт. Температурные варианты должны читаться при обычном масштабе интерфейса. Готовые изделия используют ванильные модели. Источники графики перечислены в [NOTICE.md](NOTICE.md).
