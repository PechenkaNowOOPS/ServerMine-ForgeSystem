# План развития ForgeSystem

База проекта — версия **3.0.8**. Ниже готовые возможности и предлагаемый порядок дальнейшей работы. Будущие этапы не являются обещанием сроков; конкретный объём согласуется в Issues перед реализацией.

## Готово

- [x] Интегрированный горн, предметный API и мини-игра ковки.
- [x] Железо, золото, медь; 9 изделий для каждого металла.
- [x] Нагрев, расход топлива, показатель запаса и повторный нагрев.
- [x] Три этапа ковки, качество, охлаждение и ограничение достижимого качества.
- [x] Закалка и сборка инструментов с рукоятью.
- [x] GUI горна, HUD ковки и ванильный интерфейс без ресурспака.
- [x] Ванильные заготовки с тремя температурами и молот 16×16.
- [x] ПКМ для действий в мире, ЛКМ для кнопок GUI.
- [x] Подписи предметов, блокировки сессий и журнал восстановления.
- [x] Автоматическое добавление настроек меди при обновлении.
- [x] 27 модульных тестов и встроенная серверная selftest.

## Этап 1 — проверить игровой цикл и устойчивость

Приоритет: следующий цикл разработки.

- [ ] Пройти вручную все 27 изделий: создание → ковка → закалка → сборка, где она нужна.
- [ ] Проверить GUI Scale Auto/1/2/3/4, подсказки и перекрытия текста; приложить скриншоты.
- [ ] Проверить ПКМ по воде, котлу и всем видам наковальни, включая взаимодействия двух рук и защиту территории.
- [ ] Проверить двух игроков у одного горна, полные инвентари, выход во время ковки и остановку сервера.
- [ ] На изолированном сервере проверить аварийное завершение и повторное восстановление без дублирования предметов.
- [ ] Добавить автоматические регрессионные проверки для найденных ошибок, особенно операций GUI.

**Готово, когда:** есть протокол игрового прогона с версиями сервера/клиента, нет потери или дублирования предметов в проверенных сценариях, все исправления покрыты подходящими проверками.

## Этап 2 — удобство и баланс

- [ ] Собрать отзывы о скорости нагрева, расходе топлива и сложности трёх этапов.
- [ ] Согласовать баланс железа, золота и меди; записать принятые параметры в документацию.
- [ ] Улучшить объяснение причин отказа: недостаточно металла, холодная или занятая заготовка, не хватает места.
- [ ] Обсудить предварительный просмотр результата и стоимости в GUI.
- [ ] Убрать жёсткую зависимость отметки температуры на графической шкале от стандартных 20/900/1200°C.

**Готово, когда:** игрок понимает следующий шаг без внешней инструкции, а параметры и визуальные индикаторы соответствуют настройкам.

## Этап 3 — свойства кованых изделий

Требует отдельного согласования механик и баланса.

- [ ] Определить влияние качества на прочность, урон, скорость или другие свойства.
- [ ] Продумать ремонт и совместимость с зачарованиями и обычной наковальней.
- [ ] Согласовать опциональный износ кузнечного молота и способ его ремонта.
- [ ] Описать миграцию ранее выданных предметов перед изменением их схемы.

**Готово, когда:** бонусы описаны и проверены, старые подписанные предметы сохраняют идентичность и читаются после обновления.

## Этап 4 — расширения и интеграции

- [ ] Оценить улучшение кованых предметов до алмаза и незерита.
- [ ] Определить необходимые интеграции с магазинами, экономикой и ServerPlatform через ForgeItemsApi.
- [ ] Рассмотреть дополнительные формы горна и наборы рецептов без изменения существующих данных.
- [ ] Описать и проверять совместимость с конкретными сторонними плагинами.

**Готово, когда:** для каждой выбранной интеграции есть отдельная спецификация, проверка отказов и воспроизводимый сценарий установки.

## Как брать задачу

1. Выберите один пункт и создайте Issue с ожидаемым поведением и критериями готовности.
2. Уточните зависимости и совместимость; не объединяйте несколько крупных этапов в один PR.
3. Создайте ветку `feature/...` или `fix/...`, реализуйте и проверьте изменение.
4. В PR приложите результаты проверок; обновите roadmap после фактического завершения пункта.
